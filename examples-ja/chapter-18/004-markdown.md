# 慢光工作室の週報契約
input/tasks.csv と input/notes.md のみを読み取り、ソースを変更しない。
開始前に output/actions.csv、output/report.md、output/README.md を確認する。ファイル、ディレクトリ、シンボリックリンクのいずれかが存在すれば停止して報告し、上書き・削除・別名保存をしない。
今回、開始時に3つの出力先すべてが存在しないことを確認して新規実行した場合に限り、今回作成した出力を修正してよい。中断後の再起動は新しい実行とみなし、以前の部分成果を引き継がない。
再実行は、人が未使用の新しい期のフォルダーを別途作成し、その期の input ソーススナップショット、task-spec.md、verify.py を保存して行う。output は空の状態から開始し、旧期の内容は変更しない。
README には、上記の再実行・停止ルールと今期のソーススナップショットの場所を記載する。旧フォルダーでもう一度実行してはならない。
status が doing または todo の作業のみを列挙し、未知の status があれば停止して報告する。
output/actions.csv を出力し、ソース順を維持する。列は id,task,owner,due,status,sources に固定する。
owner が空なら「待確認」、due が空なら「待確認」とする。
未承認の提案日を正式な期限にせず、期限超過の推定もしない。
sources は tasks.csv:ID;notes.md:ID とし、対応するソース識別子を保持する。
さらに output/report.md を出力し、二級見出し「本週待辦」「待確認」「來源」を使う。
G03 の担当者と G04 の期限は、提案が未承認である旨を説明して、待確認として明記する。
さらに output/README.md を出力し、再実行方法、受け入れ確認コマンド、現在の制限事項を記載する。
出力はローカルの下書きのみとし、メール送信、公開、スケジュール設定、スキル保存を行わない。
完了後、受け入れ確認を実際に実行し、失敗した場合は修正するか阻害要因を明示する。
